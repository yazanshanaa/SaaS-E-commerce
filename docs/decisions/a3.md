# A3 — Media pipeline

Implementation decisions taken while building the media pipeline. Folded into
`docs/DECISIONS.md` at merge review.

Scope: `src/server/media/**` (including `storage/` and `processors/`),
`src/app/api/media/**`, `messages/ar/media.json`, `tests/**/a3-*.test.ts`.

---

## The storage driver

- **The R2 driver is the only file in the codebase that imports the S3 client.** It lives at
  `src/server/media/storage/r2-driver.ts`, which is the path both `eslint.config.mjs` and
  `tests/unit/guardrails.test.ts` already single out. Everything else — B1's purge, B2's library,
  the Phase 1 export route — talks to `StorageAdapter`.
- **The S3 client is built on first use, never at import.** A module that opens a client at
  import time makes every unit test and every build step depend on credentials existing. The
  adapter can be constructed with no configuration at all; it only complains when someone
  actually asks it to move bytes.
- **`registerMediaStorage()` deliberately does NOT call `storage()` when the driver is local.**
  Returning "the adapter now in force" was the obvious signature, and it was wrong: it would
  materialise the local driver as a side effect of an import, and in a production deployment
  misconfigured to `STORAGE_DRIVER=local` it would turn a clear runtime refusal into a module
  that throws while being imported.
- **`deleteByPrefix('')` throws.** An empty prefix is the whole bucket — every tenant at once. The
  callers all build their prefix with `tenantPrefix()`, but the one that eventually does not is
  the one that matters, and the cost of the guard is one comparison.
- **`publicUrl()` on the R2 driver refuses to fall back to the app server when
  `CDN_PUBLIC_BASE_URL` is unset.** A fallback would break invariant 4 in production while
  looking like it worked. The local driver keeps its dev-media fallback, because that is the
  whole point of the local driver.
- **The SigV4 ceiling is stated in the driver as `SIGV4_MAX_TTL_SECONDS = 604800`** next to a
  clamp that never lets a URL past `MAX_SIGNED_URL_TTL_SECONDS` (one hour). A unit test asserts
  both, so nobody can quietly raise the platform limit toward the protocol limit and rediscover
  Q18 the hard way.

## Object layout

Keys are built only from `mediaPrefix()`, never by hand, and the layout is one folder per item:

```
tenants/{tenantId}/media/{mediaId}/source.jpg    the upload — discarded after processing
tenants/{tenantId}/media/{mediaId}/thumb.webp    400
tenants/{tenantId}/media/{mediaId}/card.avif     800
tenants/{tenantId}/media/{mediaId}/full.webp     1600  <- Media.key once ready
```

- **The `{mediaId}` segment is what makes orphan cleanup exact and cheap.** An object is an orphan
  when its media id has no `Media` row: one set-membership test per object rather than a query
  per object.
- **`Media.key` moves.** It points at the source object while the item is pending, and at
  `full.webp` once it is ready. The alternative — keeping it on a source object that invariant 4
  requires us to delete — leaves every ready row pointing at something that does not exist.

## The upload path

- **Both plan limits are checked twice: once before a byte is written, once inside the
  transaction that reserves the quota.** The early check is what stops an over-limit file from
  being uploaded to R2 and only then refused (bandwidth the limit exists to protect, and a
  billable write). The transactional re-check closes the race where two concurrent uploads both
  read the same "before" value and both slip under the last megabyte.
- **A missing feature value fails CLOSED.** `can()` returns the stored value as-is, so
  `undefined` for `image_max_mb` means we could not establish what this tenant is entitled to —
  not "unlimited". (This is the opposite of `change_requests_per_month`, where a stored `null` is
  a real answer meaning unlimited. Absent and null are different, and the code distinguishes
  them.)
- **Both refusals name the number.** `errors.fileTooLarge` carries the file size AND the plan's
  per-file limit; `errors.storageFull` carries the quota, what is already used, and what this
  file needed. The per-file check runs first, so a merchant with one oversized photo on a full
  account is not sent to delete images they did not need to delete.
- **Plan limits are rendered as the plan sells them.** `formatBytes()` from the i18n layer divides
  by 1024, so a 3000MB plan reads as "2.9 غيغابايت" — accurate, and on the one line where a
  merchant compares it against what they bought, wrong. `formatPlanMegabytes()` renders whole
  thousands as gigabytes and everything else in megabytes; real byte counts still go through
  `formatBytes()`.
- **A failed enqueue rolls the whole upload back** — object, row and reservation. A `Media` row
  with no job behind it is a tile that says "قيد المعالجة" forever and quota the merchant cannot
  get back.
- **`Media.failureReason` stores a CODE, not a sentence.** The column outlives any copy change,
  and a merchant must never be shown a raw English string from a worker;
  `mediaFailureMessage()` turns it into Arabic from `messages/ar/media.json`.

## SVG

- **Uploaded vector documents are refused with their own error code, not lumped into
  "unsupported".** They have no magic number, so they are sniffed as markup. The merchant gets
  the real reason (it can carry executable markup, and it would run on the storefront's own
  origin once the CDN served it) instead of a generic shrug.
- **`ingestInternalImage()` is the platform's own door and accepts them.** B3's demo placeholders
  are generated SVG (`src/server/demo/placeholder.ts`) and must reach the same pipeline. There is
  no HTTP route into that function and there must not be one: the reason uploaded vectors are
  refused is that they came from outside.
- **Rasterising platform SVG relies on librsvg's system fonts.** The Dockerfile already installs
  `fonts-noto-core`; without it Arabic text in a generated placeholder renders as boxes.

## Processing

- **The processor is idempotent.** A ready item short-circuits; a partial run is overwritten,
  because variant keys are deterministic and `MediaVariant` rows are replaced wholesale.
- **Permanent failures are recorded, transient ones are re-thrown.** A file that will not decode
  will not decode on the fifth attempt either, so it is marked `failed` and the job completes.
  A `StorageError` goes back to BullMQ, and the transaction rolls back with it so the row returns
  to `pending`.
- **EXIF is applied and then dropped.** `.rotate()` with no argument consumes the orientation tag;
  sharp writes no other metadata unless asked. A product photo taken on a phone carries GPS
  coordinates, and these variants are served from a public CDN.
- **`Tenant.storageBytesUsed` is adjusted with one SQL statement**
  (`GREATEST(0, used + delta)`), never read-modify-write. Concurrent uploads would otherwise lose
  an increment — a quota that leaks quietly, in exactly the busy account where it matters. The
  counter holds the upload size while pending and the sum of the variants once ready, so it
  reflects what is actually stored rather than what was sent.

## Orphan cleanup

- **`_exports/` is skipped, checked first, via `isExportKey()`.** Those objects are owned by
  `src/server/billing` and have no `Media` row by design. This is written now, before B1 exists,
  because its author would otherwise have no reason to suspect a sweep was already walking their
  prefix — and the failure mode is deleting a suspended merchant's only copy of their catalogue
  in the middle of a retention window the platform promised was a month long.
- **The sweep enumerates STORAGE PREFIXES, not live tenants.** A prefix with no `Tenant` row is
  exactly what a purge that raced an in-flight upload leaves behind: objects under an id no query
  will ever return. Walking live tenants steps straight past them.
- **Two grace windows.** An object younger than one hour is left alone (the upload writes the
  object before it commits the row). A prefix with no tenant row waits a full day before being
  swept wholesale — a purge that is merely slow must never be mistaken for one that finished.
- **Unrecognised key shapes under a tenant prefix are logged and left.** Nothing in this codebase
  writes there; guessing at an unknown owner is how a sweep becomes an outage.
- **Both scopes live in one module.** `src/server/queues.ts` registers processors by
  (queue, job name) and is a frozen shared file, so the `media/cleanup-orphans` entry has to serve
  both the SystemJob fan-out and the per-tenant sweep. The payload's own `scope` discriminant —
  the same one the dispatcher used to decide whether to hand us a transaction — picks the half.

## The library and alt text

- **Deleting an image a product still uses is refused by default**, naming how many products.
  `ProductImage` cascades from `Media`, so deleting anyway would silently strip the photo off a
  live product page: a merchant tidying their library would blank their own shop without being
  told. `force: true` is the explicit override.
- **Media objects are deleted one `delete(key)` at a time after the commit, never by prefix.**
  The media folder is a child of the tenant prefix, and a prefix delete built from a truncated
  string is how one wrong character removes an entire shop.
- **Alt text must contain Arabic**, enforced in `assertProductImageAlt()` and exported as
  `productImageAltSchema` so B2's product form and B3's pack import share one rule. `IMG_2043`
  passes "not empty" and helps neither a screen reader nor the shop's own search, and the
  accessibility floor (IS 5568 / WCAG 2.0 AA) is an Arabic-language surface.

## The endpoint

- **`/api/media/upload` establishes everything itself.** `/api/**` is unprefixed and answers on
  every hostname, so the handler reads the resolved surface (refusing a storefront hostname),
  takes the tenant from the SESSION and never from a header or a form field, and checks
  `checkMerchantAccess(..., 'media')` — `media` is a scope `staff` legitimately holds (Q13), so
  the question is not "is this an owner".
- **A plan-independent 25MB ceiling is applied to `content-length` before the body is buffered.**
  The per-plan limit is 2/5/10MB and is checked afterwards against the real byte count; this
  bound exists so an oversized body cannot be held in memory while we work out who is asking.
- **Rate limiting degrades rather than failing closed.** Redis holds the shared counter; when it
  is unreachable — the normal state in development and in this repository's test suite — an
  in-process window still binds, weakly (N processes means N budgets). Failing closed would stop
  every merchant from uploading a product photo because a cache blinked.

## Which test assertions are driver-agnostic, and which are not

| Assertion | Where | Driver-agnostic? |
|---|---|---|
| `deleteByPrefix` removes every object under a tenant prefix | `a3-storage-local`, `a3-r2-driver`, integration | **Yes** — contract, checked against a real filesystem and against the S3 command stream |
| `delete(key)` removes exactly one object | same | **Yes** |
| `signedUrl` clamps the TTL | `a3-storage-local`, `a3-r2-driver` | **Yes** (the clamp); the URL FORMAT is not — local signs an HMAC, R2 presigns SigV4 |
| `signedUrl` resolves only its own key and stops at its TTL | `a3-storage-local` | **Local-specific mechanism**, same semantics. On R2 the equivalent is enforced by SigV4 itself, which cannot be exercised offline |
| `publicUrl` refuses a non-media key | both | **Yes** |
| `publicUrl` refuses when no CDN origin is configured | `a3-r2-driver` | **R2-only** — the local driver deliberately falls back to `/dev-media` |
| Encryption requested for `_exports/`, cache-control for media | `a3-r2-driver` | **R2-only** — the local driver ignores both options |
| Prefix listing pages, deletes batch at 1000 | `a3-r2-driver` | **R2-only** — an S3 protocol limit |
| Variants, counters, limits, magic bytes, orphan rules | integration | **Yes** — all of it goes through the `StorageAdapter` interface |

There is no R2 bucket and no network bucket in this environment, so the R2 driver is exercised
against an in-memory fake that answers the real command objects, with one exception:
`signedUrl` presigns for real, because SigV4 is arithmetic over the client's credentials and
needs no network. The clamp is therefore measured on an actual URL.

## Not built, deliberately

- **The media library SCREEN.** `src/app/dashboard/**` is B2's surface. Everything it needs is
  exported from `@/server/media`: `listMedia`, `deleteMedia`, `setMediaAltText`, `storageUsage`,
  `productImageAltSchema`, and the Arabic copy in `messages/ar/media.json`.
- **A repeatable schedule for the orphan sweep.** Registering a repeatable job belongs to whoever
  owns the worker bootstrap; `sweepOrphanPrefixes()` is the entry point, and the intended cadence
  is daily, off-peak, alongside B1's lifecycle sweep.
- **Anything touching `Subscription` or `Tenant.state`.** Invariant 5: lifecycle state changes
  live in `src/server/billing` and nowhere else. The pipeline reads the tenant row and writes one
  column of it (`storageBytesUsed`), which the schema comment assigns to the media jobs.
