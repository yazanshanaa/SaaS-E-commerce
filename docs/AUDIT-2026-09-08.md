# Souq Bartaa — audit, corrections and remediation

**Date:** 2026-09-08 · **Supersedes:** `docs/STATUS-AND-AUDIT-2026-09-07.md`
**Scope:** working tree, GitHub repository, live production (`souq48.shop`), and the design system

---

## 0. Why this document exists

The 2026-09-07 report was **directionally right and factually unreliable**. Its conclusions hold —
the work is real, none of it is deployed, and the serious exposures are governance rather than code.
Its specifics do not: it asserted things that are false, and its security section found six items, of
which three were GitHub settings.

A 15-dimension adversarial audit of the same tree found **106 distinct findings**, including one
critical and roughly a dozen highs that the earlier report did not reach. This document records what
was checked, what was wrong, what was fixed and verified, and what is left — including the things
deliberately **not** done.

## 1. Method, and its one caveat

Fifteen parallel finders (tenant isolation, authz, input validation, HTTP edge, media, commerce,
infrastructure, privacy, Next.js correctness, entitlements, report fact-check, frontend/RTL,
performance, tests/CI, dependencies), each required to cite a file and line it had actually read,
followed by adversarial verifiers whose default answer was "not real". Two independent
fresh-context design-critic passes on rendered screenshots. Everything was checked against a running
system rather than by reading alone.

**The caveat, stated because it changes how the numbers read.** Fixes were applied *while* the
verification stage was running, so several findings were refuted with reasons like *"the quoted
evidence does not match the file"* — because the file had been fixed an hour earlier. A raw
confirmed/refuted ratio from that run therefore **understates** the real findings and must not be
quoted as an accuracy measure.

Genuine refutations worth recording:

- **Push-endpoint SSRF** — rejected as intentional, documented, with the stated compensating
  controls actually present.
- **`withTenantTxn` + a super_admin actor disables RLS** — the behaviour is real (the generic policy
  carries `OR current_setting('app.actor_role') = 'super_admin'`), but no exploit path exists today:
  all thirteen change-request appliers carry the `tenantId` predicate. Treated as a documentation
  and defence-in-depth problem, not a live hole. See §5.

## 3. Fixed and verified

All gates green after every change: `typecheck` ✓ · `lint` ✓ (1 pre-existing warning) ·
**1532 / 1532 tests, 81 files** (17 new regression tests) · design QA **9.5/10, 0 blockers**.

### Security

1. **Seeded super-admin credential.** `prisma/seed.ts` fell back to `admin@souqbartaa.test` /
   `ChangeMe!2026`, both published in this repository, and `.env.example` shipped the literals. Now
   fails closed in production. Separately, the credential upsert did `update: { password }`, so
   `pnpm db:seed` — the documented way to reseed plans, carriers and legal pages — silently undid
   step 4 of `DEPLOY.md`. Now `update: {}`, with `SEED_SUPER_ADMIN_FORCE_PASSWORD=1` as the named
   escape hatch.
2. **Host Docker socket mounted into Uptime Kuma.** `:ro` makes the socket *file* read-only; the
   Docker API is not a file. Anything that can open it can create a privileged container and become
   root on the VPS — from a container Caddy publishes behind basic auth. Mount removed.
3. **`.dockerignore` missed `.pgdata-dev`** (77 MB of a real seeded cluster). The same bug
   `.gitignore` already fixed in the 2026-08-21 review and closed there with a `.pgdata*/` glob,
   never carried across. It matters most one stage on: `standalone-source` runs `COPY . /src` and
   tars the context into the bundle **a merchant receives**, reasoning in its own comment that
   *"`.dockerignore` already excludes … so they cannot be in here"*. Fixed in both places.
4. **`javascript:` / `data:` hrefs** could reach a storefront `<a href>` through three of seven
   announcement writers — including the change-request queue, where a super admin approving what
   reads as a text change writes the scheme. One shared scheme-checked validator now governs all.
5. **Tenant context headers** (`x-souq-*`) are now stripped at Caddy, closing the paths the proxy
   matcher excludes. `x-souq-public-path` was also absent from the app-layer strip list.
6. **Password-reset rate limiting** keyed on `x-real-ip` = the Cloudflare **edge** address, i.e. one
   shared bucket per edge node, and it was the only bound on `/request-password-reset`,
   `/forget-password` and `/reset-password`. `proxy.ts` now stamps `x-souq-client-ip` from the
   central `getClientIp()`; better-auth reads that first.
7. **Cookies.** The consent cookie derived `secure` from `request.url`, which is plain HTTP behind
   Caddy — so it shipped **without `Secure`** on the only deployment where it matters. The
   demo-token cookie, a bearer credential to a private showcase, carried no flag at all. Both now
   read `PUBLIC_SCHEME`.
8. **Fingerprinting.** `X-Powered-By` and `Via: 1.1 Caddy` removed.
9. **CI/deploy least privilege.** Neither workflow declared `permissions:`; both now `contents: read`.
   `.github/dependabot.yml` added.
10. **2FA claim corrected.** The auth config asserted 2FA was "mandatory for the super admin". It is
    neither enforced nor **enrollable** — the verify half is complete, but nothing calls
    `/two-factor/enable`, so it can only be turned on by hand in Postgres, which would lock the
    account out. Comment corrected; see §4.

### Correctness

11. **Archived products were still buyable** — checkout, quote and the single-product path filtered
    on `published` but never `archivedAt`, so a cart persisted in localStorage bought a product at
    the price it was archived for.
12. **Uploads between 10 MB and 25 MB were silently truncated.** Next 16 buffers the proxy-cloned
    body at 10 MB by default and truncates beyond it; `ABSOLUTE_MAX_UPLOAD_BYTES` is 25 MB. The
    merchant saw an Arabic error blaming their photo. `proxyClientMaxBodySize: '26mb'` set, with a
    test that fails if the ceiling ever outgrows the buffer again.
13. **`/demo-gate` was statically prerendered** with `DOMAIN=build.invalid` baked in from the
    Dockerfile — so the call to action on the page every prospect sees pointed at a dead host. Both
    proxy rewrite targets also shipped `Cache-Control: s-maxage=31536000` (observed live). Both now
    `force-dynamic`.
14. **The backup sidecar's `REDIS_URL` carried no password** while Redis runs `--requirepass`, so
    every connection was refused `NOAUTH` and the whole Q23 control channel was dead — the owner's
    «شغّل الآن» button and the backups status card, silently.
15. **Coupon per-phone limit** was one use per *spelling* of the number. Now normalised, matching
    both forms so pre-existing redemptions still count.

### Design and accessibility

16. **Live WCAG AA failure on every dark-palette storefront.** `globals.css` sets
    `a { color: var(--sb-primary) }` — the *platform's* orange — and the storefront reset only
    covered `a:not([class])`. `.sf-cat` is a classed anchor with no colour of its own, so category
    cards rendered platform-orange at **2.33:1 measured live**. Fixed; QA contrast failures 9 → 0.
17. **All nine templates rendered headings in the platform's Alexandria.** A matching declaration
    beats inheritance, so `.sf-root`'s `--t-font` never reached a heading; `h4` was absent from the
    globals rule and inherited correctly, putting two faces one element apart in a card grid.
    Verified fixed: the QA font census lost Alexandria entirely.
18. **Arabic letter-joins broken** on `.sf-offline__shop` — the shop's own name, set with positive
    tracking on a cursive script.
19. **Diwan hero collapsed to a 57×68px orphan** in ~700px of empty column for any shop with no
    photo, which is most shops.
20. **Testimonial measure collapsed to 154px** at 390px — UA `figure`/`blockquote` margins.
21. **Instagram shipped a purple gradient** ending on `#6228d7` — a hard ban in both CLAUDE.md and
    `design/design.json`, on any shop that adds a handle.
22. **Prices had no tabular figures**, the one craft detail `taste.md` names outright.
23. **Announcement-bar dismiss was a 28px tap target** — hit area grown to ~44px with a
    pseudo-element, painted size unchanged, verified by hit-testing.

A regression test now pins the *class* behind 16/17 — the platform sheet leaking into the storefront
through the cascade — because it has now shipped three times.

### Toolchain

24. **The e2e suite is runnable again**, and ran end to end for the first time: **126 passed, 6
    failed, 18 skipped**. The port-conflict guard now names the real problem (and probes both
    `0.0.0.0` and `127.0.0.1`, after the first version let an orphan through). The `webServer`
    budget is 900 s with the measured breakdown recorded.
25. **Two e2e failures fixed and verified passing.** Not product bugs: the page carries two links
    named «اطلب عبر واتساب» — the product button and the shell's floating FAB — so strict mode
    refused to guess. Four further assertions had the same ambiguity, including one inside failure
    #116; all are now scoped to `<main>`, which the FAB sits outside.

## 4. Requires the owner's decision — deliberately not done

1. **CRITICAL — `env_file: [.env]`** hands the internet-facing `web` container the Postgres
   **superuser** password, the migrate role's password and the backup encryption keys. The compose
   comments correctly explain why `env_file` is there; the fix is to split the env surface so infra
   secrets reach only the services that need them, which changes the deployment procedure.
2. **2FA for the super admin.** Enrolment must be built *before* enforcement — enforcing first locks
   the platform owner out of production with no path back that does not involve editing the database
   by hand.
3. **Repository visibility.** It is public, and `docs/DEPLOY-HOSTINGER.md` says *"the repo is
   private; a deploy key is the clean way"* — so this is an accident, not a decision. No secret has
   ever been committed, which is the good news.
4. **HSTS `preload`** — left alone. The Caddyfile's reasoning is sound and the flag is irreversible
   on a browser timescale across merchant-owned domains.
5. **The storefront redesign** the critic asks for (hero composition, mobile grid, sticky order bar,
   card affordance, section rhythm). Correct criticism, but product-shaping across nine templates and
   every live shop. Recorded with selector-level instructions in `design/critic.md`.
6. **Cloudflare Web Analytics** is auto-injecting `beacon.min.js` into merchant storefronts. Our CSP
   blocks it — which is why it shows as a console error rather than as tracking — but it should be
   turned off at Cloudflare rather than left to the policy to catch.

## 5. Open findings not yet acted on

Recorded so they are not lost. Severities are the finders' own, after adversarial review.

**High.** Live preview renders any template regardless of `templates_allowed` (cheapest-plan
bypass) · `delivery_zones` enforced only in the dashboard while the storefront keeps charging zone
prices · gateway settlement marks an order paid for whatever amount the callback claims, with no
cross-check against the order · cart checkout spends `Product.stockQty` for products whose real
balance is the variant sum · export/backup archives share the bucket the media CDN publishes ·
`/export/{token}` bearer credential copied verbatim into the global `webhook_deliveries` table ·
`GET /api/dashboard/export` builds a customer-PII archive with no cross-site guard · production
images ship the entire devDependency tree · three RLS regression tests pass vacuously on an empty
result set · 36 of 39 super-admin audit actions have no test · CI has no secret scanning and no SAST
on a public repository · deploy is reachable from a fork pull request · storefront page views fire
20 separate entitlement lookups · `/dashboard/products` loads the entire catalogue with no `take`.

**Medium and below.** `withTenantTxn` + super_admin actor removes RLS across the admin-apply surface
(comments corrected, structural change deferred) · self-edit rewrites `deliveryArea` without
re-quoting the fee · coupon dates parsed as UTC midnight, so a promotion dies at 03:00 local on its
last day · «دفع إلكتروني» places an order with no payment step · a cancelled order never releases its
coupon use · two production deploys can run at once · unbounded `>=` pnpm overrides crossed a major ·
`₪` is claimed in every `@font-face` unicode-range and present in none of the eight woff2 files ·
form-control borders measure 1.54–2.00:1 · the axe gate runs on 3 of 9 templates · ~100 user-facing
Arabic strings sit outside the hardcoded-string gate's scan roots.

## 6. Recommended order

1. Split the env surface (§4.1) — the only critical item.
2. Make the repository private, and rotate the seeded super-admin password regardless (§4.3).
3. Create the `production` environment with a required reviewer, and protect `main` — the
   2026-09-07 report's §4.1 and §4.2 stand, unverifiable from here but almost certainly still true.
4. Enable Dependabot alerts (the config file is now in the repo; alerts are a repository setting).
5. Diagnose the four remaining e2e failures — the suite runs now, so they are observable.
6. Work §5's High list, starting with the two money bugs (gateway amount, variant stock).
7. Upload real product photography. Imagery scored 3/10 in both critic rounds and no code change
   substitutes for it.
