Stop preloading the chrome fonts on storefronts

`src/app/layout.tsx` preloaded two faces with a comment saying they were needed
"on every private surface". They are - but that layout is shared by all three
surfaces and is synchronous by design, so it cannot tell them apart. Every
storefront preloaded the admin/dashboard faces it never paints, on top of its
own template face from `templates/shell.tsx`, whose header says about exactly
this: "Preloading three families would spend the Fast 3G budget on two fonts
nobody will see."

Three preloads where the shell promises one. `tests/e2e/a2-storefront.spec.ts`
pins it twice - `Expected length: 1, Received length: 3` - and both cases had
been red since the storefront budget was written, on a suite that had never run
anywhere it could be read.

The two links move into `_components/chrome-font-preload.tsx`, rendered by the
admin and dashboard layouts. React hoists `<link>` into `<head>` from anywhere
in the tree, so the hint lands in the same place and can no longer reach a
surface that does not use it.

Five render sites, and the split between them is the point: both admin branches
(the login page is the first thing an admin ever paints) and both authenticated
dashboard branches get it. The dashboard's `preview` branch does NOT - that one
renders the storefront shell, and giving it the chrome faces would rebuild the
same bug on the one route Phase 11 added.

This is CLAUDE.md's budget, not a test detail: LCP under 2.5s on Fast 3G, fonts
subset and preloaded. Two unused Arabic faces on the critical path cost a real
phone in Bartaa real time.
