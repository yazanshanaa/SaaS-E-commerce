Add fill-env.sh: one paste per key, and no key in the shell history

Ten values in `.env` cannot be generated - they need a Cloudflare account, an R2
subscription, a Resend account, and an age keypair whose secret half must never
touch this server. The three ways an operator normally fills them are all worse
than they look:

  nano       - navigating by line number in a 376-line file, and one stray
               keystroke edits a line nobody will notice until a container
               refuses to start.
  sed        - the key lands in ~/.bash_history and stays there. It is the kind
               of leak nobody cleans up because nobody remembers it happened.
  a template - a file full of secrets sitting on disk waiting to be forgotten.

So: prompts, one at a time, read with `read -s` so nothing echoes and nothing
reaches the history. A key already set is reported and left alone, which makes
re-running safe - the operator can fill what they have today and come back.

It ends by checking exactly the six values the compose marks `:?` and saying
whether the stack can boot, rather than leaving that to be discovered by a
container exiting.

The read-only backup pair is prompted for with the reason it is separate from
the write pair spelled out at the prompt: the write pair can delete every
historical dump, and the web container is the one process exposed to the
internet.
