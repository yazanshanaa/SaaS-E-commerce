Read the visible brand, and make a refused account creation say so

Two things, both about tests reading the wrong thing.

1. b2-dashboard asserted the shop name with `.first()`. Phase 11's kit renders
   the brand TWICE by design - a top bar below 48rem and the sticky rail above
   it, with CSS hiding whichever does not apply; `rail.tsx`'s own comment on the
   top bar says "Hidden by the kit above 48rem". `.first()` takes DOM ORDER,
   which is the top bar, and at every viewport this suite runs at that is the
   hidden copy. The dashboard was working and the test was reading a copy the
   merchant cannot see. Now filtered to the visible one.

2. `phase11:181` and `phase7:313` both assert a heading straight after clicking
   «افتح الحساب», and both fail with "element not found" - while `a1-admin.spec.ts`
   does the identical thing and passes. Reading the code did not find the
   discriminator: same form, same plan (`basic` in phase7), same
   `sendPasswordLink`, and the heading is `PageHead title={account.name}` in the
   account layout either way.

   So rather than guess a fix, the assertion now names the page it landed on. A
   refused creation re-renders `/accounts/new`; a successful one redirects to
   `/accounts/{id}`, the shape a1-admin already pins. Asserting the heading
   alone spends the timeout waiting for something that was never going to
   render and then reports nothing useful. The next run answers the question
   instead of repeating it.

Fifth of the ten first-run e2e failures fixed; the sixth is now instrumented.
